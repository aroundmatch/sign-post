# design-catalog-parent-redesign

## 1. この設計書の目的

この設計書は、サインポスト公式サイトのデザインカタログ親ページ `/column/eyelash/catalog` を改善するための親ページ専用設計書です。

目的は、現在のページを単なる長文コラムではなく、まつ毛パーマ・マツエク・眉毛・まつ毛×眉毛セットの仕上がりを比較し、各詳細ページや料金・店舗・予約導線へ自然につなげる入口として再設計することです。

この段階では、本文HTMLはまだ作成しません。管理画面入力内容、セクション構成、画像配置、内部リンク、重複回避、HTML化前の確認事項を整理します。

---

## 2. 現在の `/column/eyelash/catalog` の課題整理

### 2-1. 役割が広くなりすぎている

現在のデザインカタログ親ページは、デザイン一覧、マツエクの説明、カール・本数・長さ・トレンド・FAQ・店舗案内など、多くの情報を1ページに含む状態になっています。

親ページとしては情報量が多く、子ページに分けるべき詳細まで抱えやすいため、今後は「仕上がり比較と入口」に役割を絞ります。

### 2-2. マツエク中心の印象が強い

今後のサインポスト公式サイトでは、デザインカタログを以下の4カテゴリを横断する入口として扱います。

- まつ毛パーマ
- マツエク
- 眉毛・アイブロウ
- まつ毛×眉毛セット

そのため、親ページの見出しや導入文は、マツエクだけに偏らない表現へ調整します。

### 2-3. 悩み・目的別ガイドと重複しやすい

`/guide_by_problem/design` は「似合うデザインを探したい人向けの悩み入口」です。

一方で、`/column/eyelash/catalog` は「仕上がりイメージ・デザイン一覧・比較の入口」です。

catalog側では「似合うか不安」「派手になりたくない」などの悩み解決を主役にしすぎず、見た目・印象・メニュー別の比較を主役にします。

### 2-4. 既存URLの棚卸しが必要

既存のcatalog関連URL、`/design`、`/column/catalog` など類似URLがある場合、事前に役割・主キーワード・導線を確認します。

新規URLを増やす前に、既存ページに追記すべきか、リライトすべきか、統合を検討すべきかを判断します。

## 3. 親ページの新しい役割定義

`/column/eyelash/catalog` は、以下の役割を担います。

- まつ毛・眉毛デザインの全体像を短時間で理解できる入口
- 仕上がりイメージを「印象」「メニュー」「目元タイプ」から比較できるページ
- 各詳細ページへ進む前の案内ページ
- 料金確認は `/price` へつなぐ
- 店舗選択は `/salon` または3店舗カードへつなぐ
- 予約確認は `/app` へつなぐ

お客様向け本文では、「親ページ」「子ページ」「クラスター」などの内部用語は使わず、以下のような自然な表現に置き換えます。

- 仕上がりを比べる
- 印象から選ぶ
- メニューから選ぶ
- 料金を確認する
- 店舗を選ぶ
- 予約・公式アプリを見る

## 6. 親ページで扱わない内容

- 本数別・カール別・長さ別の詳細解説を長く書きすぎない
- 特定デザインの施術事例を深く説明しすぎない
- 「似合うか不安」「初めてで不安」などの悩み相談を主役にしすぎない
- 料金表を本文内で細かく再掲載しない
- 予約可能かどうかを断定しない
- canonical / noindex を実装指示として書かない

## 8. 各セクションの目的と掲載内容

### 8-1. ファーストビュー

目的：このページが「仕上がりからデザインを選べる入口」だと伝える。

掲載内容：
- 管理画面H1と重複しない大見出し
- まつ毛・眉毛デザインを比較できる短い説明
- デザイン一覧、料金、店舗、予約への導線
- 3:2比率のメイン画像プレースホルダー

### 8-2. ページ内ショートカット

目的：長いページでも目的の場所へ移動しやすくする。

リンク候補：
- 印象から選ぶ
- メニューから選ぶ
- 目元タイプから選ぶ
- 料金を確認する
- 店舗を選ぶ
- 予約・公式アプリを見る

### 8-3. 仕上がりの印象から選ぶ

目的：お客様が「なりたい印象」からデザインを探せるようにする。

カード候補：
- ナチュラル
- ぱっちり
- 束感
- 韓国風・ワンホン風
- 上品・大人
- 目元タイプ別

### 8-4. メニューから選ぶ

目的：メニュー別に仕上がりの違いを理解できるようにする。

カード候補：
- まつ毛パーマ
- マツエク
- 眉毛・アイブロウ
- まつ毛×眉毛セット

料金詳細は本文内で完結させず、`/price` へ案内します。

### 8-5. 目元タイプから選ぶ

目的：一重・奥二重・下がりまつ毛など、仕上がりの見え方が変わりやすい方へ関連ページを案内する。

詳しい悩み解説は `/guide_by_problem/eye_shape` や `/guide_by_problem/design` へ送ります。

### 8-6. 主要デザインカタログ一覧

目的：今後作成する詳細ページや既存カタログ系ページへの入口を整理する。

掲載内容：
- デザイン名
- 短い説明
- 向いている方
- 詳しく見るリンク
- 関連メニューリンク

### 8-7. デザイン選びで見ておきたい3つのポイント

目的：親ページ内で簡潔に選び方の視点を提示する。

3つのポイント：
1. なりたい印象
2. 自まつ毛・眉の状態
3. 相談時に伝えること

### 8-8. 料金・メニュー確認への導線

目的：料金確認を `/price` に集約する。

案内文：
デザインごとの詳しい料金は、メニュー・料金ページで確認できます。池袋東口店・志木店・ふじみ野店は、同じメニュー・料金でご案内しています。

### 8-9. 店舗カード

目的：3店舗を均等に表示し、店舗選択へつなげる。

表示店舗：
- 池袋東口店

### 8-10. 予約・公式アプリへの導線

目的：予約や空き状況確認を `/app` へつなげる。

必須表現：
空き状況は予約画面または公式アプリでご確認ください。

### 8-11. FAQ

目的：親ページ内でよくある質問に短く答える。

FAQ候補：

## 9. 画像配置設計

画像は自動生成せず、`src=""` の空URLプレースホルダーを使用します。`alt` には、どのような画像が必要かを日本語で具体的に書きます。

| 位置 | 画像内容 | loading |
|---|---|---|
| ファーストビュー | まつ毛パーマ、マツエク、眉毛、セットデザインを比較できる目元写真のコラージュ | eager |
| 印象別カード | ナチュラル、ぱっちり、束感、韓国風などの目元写真 | lazy |
| メニュー別カード | まつ毛パーマ、マツエク、眉毛、セットの雰囲気が分かる写真 | lazy |
| 目元タイプ案内 | 一重・奥二重・下がりまつ毛の仕上がり比較イメージ | lazy |
| 店舗カード | 池袋東口・志木・ふじみ野の店舗写真 | lazy |

画像プレースホルダー例：

```html
<img
  src=""
  alt="【差し替え用】まつ毛パーマ、マツエク、眉毛、まつ毛と眉毛のセットデザインを比較できる目元写真のコラージュ。3:2比率、明るいサロン照明、清潔感のある仕上がり"
  width="1200"
  height="800"
  loading="eager"
>
```

## 12. `/design` や `/column/catalog` など重複候補ページの確認メモ

以下のURLは、存在する場合に必ず役割を確認します。

- `/design`
- `/column/catalog`
- `/column/eyelash/catalog/catalog_type`
- `/column/eyelash/catalog/catalog_curl`
- `/column/eyelash/catalog/color_extension`
- 本数別・カール別・タイプ別の既存URL

確認観点：
- 親ページとして残すのか
- catalog親ページに統合するのか
- 詳細ページとして役割を分けるのか
- 内部リンクで補完するのか

canonical / noindex は実装指示ではなく、検討メモとしてのみ扱います。

## 13. カニバリ回避方針

### 13-1. `/guide_by_problem/design` との住み分け

| URL | 役割 | 主な表現 |
|---|---|---|
| `/guide_by_problem/design` | 似合うデザインを探したい人向けの悩み入口 | 似合うか不安、派手になりたくない、何を選べばいいか分からない |
| `/column/eyelash/catalog` | 仕上がりイメージ・デザイン一覧・比較の入口 | デザインを見る、仕上がりを比べる、メニュー別に探す |

### 13-2. 既存ページと競合した場合の判断

1. 新規作成：既存ページと検索意図・内容範囲が明確に異なる場合
2. 既存ページへ追記：既存ページの主題内で不足情報を補える場合
3. 既存ページをリライト：既存ページの品質不足が主因の場合
4. 統合を検討：複数ページが同一意図で重複している場合
5. canonical / noindex：検討メモに留め、実装指示にはしない

## 14. HTML化する前の確認事項

- 親ページの役割が「仕上がり比較・デザイン一覧の入口」になっているか
- マツエクだけに偏っていないか
- まつ毛パーマ・マツエク・眉毛・セットの4カテゴリが均等に扱われているか
- `/guide_by_problem/design` と重複していないか
- 既存URLを無視して新規URLを増やしすぎていないか
- `/price` `/salon` `/app` への導線があるか
- 3店舗が均等に扱われているか
- 予約可否を断定していないか
- canonical / noindex が実装指示になっていないか
